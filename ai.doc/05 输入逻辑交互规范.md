# 05 输入逻辑交互规范 (Input Logic Standard)

本文档定义了 TimeFlow 项目中输入框与全局快捷键之间的交互协作规范，旨在解决“回车冲突”及“冒泡干扰”问题。

## 核心设计理念：关注点分离 (Separation of Concerns)

交互逻辑被明确划分为两层，以实现物理级别的冲突隔离。

### 1. 组件层 (局部控制与隔离)
所有输入场景必须统一使用 `infa.Input` 组件，并遵循以下行为规范：

*   **生命周期管理**：组件内部负责“输入 -> 提交 (onCommit/handleSubmit) -> 自动关闭 (isShow = false)”的完整闭环。
*   **物理隔离 (关键)**：必须在组件的 `onkeydown` 回调中拦截 `Enter` 和 `Space` 键。
    ```svelte
    <infa.Input
        onkeydown={(e) => {
            // 阻止冒泡到 window 全局监听器，避免触发提交外的全局逻辑 (如 Space 暂停)
            if (e.key === "Enter" || e.key === " ") {
                e.stopPropagation(); 
            }
        }}
        ...
    />
    ```

*   **设计目标**：确保“为了回车提交”而产生的信号不会泄漏到全局层。

### 3. 已知问题与调试 (Known Issues)

> [!IMPORTANT]
> **Checkpoint 输入框回车冲突 (紧急/高优先级)**
> 目前 Checkpoint 输入框在通过全局 `Enter` 信号开启后，再次按 `Enter` 提交时，存在即使使用了 `untrack` 和 `stopPropagation` 仍偶尔重开或无法关闭的问题。
> - **可能原因**：Svelte 5 响应式系统在组件卸载（show=false）与全局 Effect 再次读取信号之间存在微秒级竞态。
> - **当前规避手段**：已增加 `setTimeout` 加固焦点及 Store 层防抖，但未完全解决。后续重构建议考虑通过更稳定的状态锁或显式的组件引用来传递焦点。
全局快捷键监听器（通常位于 `+page.svelte` 或组件的 `svelte:window` 监听中）应仅处理“开启”逻辑：

*   **只管开启**：当全局收到 `Enter` 信号时，先通过 `document.activeElement` 确认焦点不在输入框内，然后执行“打开/聚焦”操作。
*   **不处理 Toggle-Off**：全局层不应负责关闭已打开的输入框。关闭动作由组件内部提交后自主完成，或由 `Escape` 键统一控制。
*   **设计目标**：由于组件层已经物理拦截了提交回车，全局层接收到的 `Enter` 信号必然是用户在“非输入状态”下发出的，此时可以安全地触发开启逻辑。

## 适用场景
*   **TaskInput**: 主任务添加。
*   **CheckpointInput**: 任务记录点添加。
*   **TaskHeader (Title Edit)**：任务标题行内编辑。

## 开发约定
在后续开发新类型输入框时：
1.  **必须**使用 `infa.Input`。
2.  **必须**在 `onkeydown` 中执行 `e.stopPropagation()` 拦截 `Enter`。
3.  **禁止**在全局 `window` 监听器中编写逻辑来处理“正在编辑中的回车”。
